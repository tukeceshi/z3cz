# 重拍节点：主视频引用方案

> 状态：待确认 · 确认后执行，本文档本身不含实现

## 目标

取消 `retake_source` 专用连线。重拍节点与普通视频节点共用**引用口**，其中**第一个视频引用**承担「原片」角色，其余引用（图片/音频/额外视频）行为不变。

---

## 四条规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | 拖动条绑定第一个视频引用 | 时长探测、裁剪区间、卡片原片预览，均来自该引用 |
| 2 | 第一个视频引用不可删 | UI 隐藏删除；删边/断连拦截；删源节点时提示或阻止 |
| 3 | 提交时处理不同 | 先按拖动条裁出片段，作为 `<视频1>` 提交；其余视频引用排在后面，不参与裁剪 |
| 4 | 计价用拖动条时长 | 第一个视频引用的计费时长 = `draftRange` 选中时长，不用整段原片时长 |

---

## 主视频引用如何认定

- 重拍模式下，连到**引用口**的边里，**第一个视频类引用**即主视频。
- 认定顺序与现有引用列表一致（当前 `collectAiVideoUnifiedReferenceChips` 的遍历顺序）。
- 无主视频时：拖动条不可用，不可生成，卡片无原片。

## 与当前实现的差异

| 项 | 当前 | 改后 |
|----|------|------|
| 原片来源 | `retake_source` 专用口 | 引用口第一个视频 |
| 创建重拍节点 | 自动连专用口 | 自动连引用口（正常引用） |
| 引用计数 | 虚拟 +1 视频位 | 第一个视频即占位，去掉虚拟计数 |
| 引用 chips | 不含原片 | 含原片，第一个视频带锁定态 |
| 计价 | 已从拖动条取时长，但媒体来自专用口 | 媒体与时长均来自第一个视频引用 |

**删除：** `retake_source` handle、专用边校验、`ai-video-retake-source-edge.ts`、`resolveRetakeSourceMedia`。

**保留：** 生成后仍为重拍模式、`cardPreview` 切换、提示词存 `inputs.prompt`、history 写入逻辑（含上轮审查的本地拼接修复）。

## 改动范围（确认后按此执行）

### 数据与类型
- 移除 `AI_VIDEO_RETAKE_SOURCE_HANDLE_ID`
- `retake_draft` 可记录 `primaryVideoEdgeId`（可选，用于边顺序变化时稳定认定；若无则仍按列表第一个视频）

### 创建重拍节点
- `use-video-trim-to-sibling-node` / `useCreateLockedRetakeCopyNode`：自动把源视频连到**引用口**，不再连专用口

### 读取原片
- 新增 `resolveRetakePrimaryVideoRef`（读第一个视频引用边 + media）
- 替换所有 `resolveRetakeSourceMedia` 调用点：config panel、trim panel、widget、卡片展示、生成 pipeline

### UI
- 引用 chips：第一个视频显示锁定（无删除按钮）
- 断连/删边：拦截主视频引用边
- 卡片「原片态」：展示主视频引用，不再依赖专用连线 context

### 生成 pipeline
- 裁剪源 = 主视频引用 media + `draftRange`
- 提交 URL 顺序：裁剪片段在前，其余引用视频在后（沿用现有 `mergeRetakeReferenceVideoUrls` 思路）
- 图片/音频引用逻辑不变

### 计价
- `referenceVideoMedia` = 主视频引用 media（有则 `[media]`，无则 `[]`）
- `referenceVideoDurationSec` = 拖动条选中时长（已实现，改数据源即可）

### 迁移（如有已存工作流）
- 读取时：若存在 `retake_source` 边 → 迁移为等效引用口连线，并删除旧边

## 边界情况

- **用户再连一个视频到引用口**：排在主视频之后，正常可删，提交时作为额外 `<视频N>`
- **主视频源节点被删**：重拍节点进入错误态，提示重新关联
- **拖动条改区间**：同步更新 `inputs.prompt` 内时间段（现有逻辑保留）
- **生成后「重做」回源片态**：卡片与拖动条仍读主视频引用，不读 history
