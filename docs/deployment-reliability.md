# 生产部署可靠性

本变更由发布包中的生产 Compose、安装/升级/回退脚本生效。开发 Compose、开发入口、已有数据库位置及密码不变；不会在代码检查时修改现有容器。

## 启动与验收

- 四个服务默认 `always`，日志保留最多 3 个 10 MB 文件；PostgreSQL 停止宽限期 60 秒，其他服务 30 秒，Node 服务使用 `init` 转发信号并回收子进程。这不等同于业务请求完全排空。
- API 使用已有的 `POSTGRES_WAIT_FOREVER=1`，运行时等待数据库；健康检查 `/health/ready` 必须完成认证查询。等待并不能修复错误密码、缺失文件或损坏数据库。
- 域名服务检查本地 socket；Caddy 只在容器回环地址 `127.0.0.1:8081` 提供内部检查，转发 API 就绪检查，不受公网域名、证书或维护页影响。该端口不发布到宿主机。
- 安装、更新、回退等待健康的期限默认为 300 秒，可用命令环境变量 `Z3CZ_DEPLOY_TIMEOUT` 设置。健康状态变为 unhealthy 本身不会触发 Docker 重启；数据库恢复后应通过应用连接恢复正常。
- `depends_on` 用于 Compose 启动编排；引擎重启恢复不能只依赖它。Docker 引擎开机启动、Desktop 登录启动及 WSL 生命周期需另行保障。

## 挂载与旧版兼容

Caddy 使用发布包的 `caddy/`，域名服务使用发布包的 `scripts/`；目录随包提供，不依赖目标机器临时创建发布内容。包根目录的 `Caddyfile` 仍保留并校验与目录内配置相同。

PostgreSQL 同时接受密码文件和仅含密码的目录，继续使用官方入口初始化数据库。原始密码 `/etc/z3cz/postgres.password` 保留。新部署脚本的显式准备步骤复制相同内容到 `/etc/z3cz/postgres-secret/postgres.password`，目录权限 0700、文件权限 0600；不会重置数据库密码，也不会将包含 JWT 等信息的整个配置目录暴露给数据库。

发布包的 `password-mount.version` 标识新挂载契约。新脚本对新包使用密码目录，对旧包继续使用原始文件。旧 `update.sh` 传入的 `Z3CZ_POSTGRES_PASSWORD_FILE` 仍可指向原文件，新模板兼容该输入。策略校验 `validate-policy` 仍然只校验，不准备文件或修改系统。

**第一跳升级边界：** 已安装版本的脚本负责启动本次升级。因此旧脚本升级到新包时，仍沿用旧脚本的超时、失败处理和密码文件挂载；新包不会神奇地替换正在执行的脚本。新安装和以后由新脚本执行的部署才使用目录密码挂载及新的失败处理。需要第一跳也采用新流程时，应先下载并验证目标正式包，再直接执行其中的 `scripts/update.sh <目标版本>`，由该入口再次校验正式包；不要先覆盖已安装版本的脚本。

Linux 原生 Docker 是发布自动验收环境。Docker Desktop/WSL 的历史单文件挂载故障与停止状态是不同问题；目录挂载减少单文件路径依赖，但**整机重启验收之前不能声明 Desktop/WSL 问题彻底解决**。

## 失败与重试

安装、更新、回退共享部署锁，防止互相覆盖。安装记录未完成目标，失败恢复原 `current` 指向；同版本可重试，未知已有目录不会被覆盖，已有正常安装应走升级入口。安装重试会再次执行迁移，因此迁移应保持幂等。

部署前检查包文件、Compose、镜像、容器实际读取挂载及 Caddy 配置。更新在维护前完成这些检查。更新失败时，只有旧版本恢复健康、认证数据库查询成功且数据库声明兼容，才能解除维护。新旧版本都失败时保留维护和备份。已有维护标记会阻止另一轮更新，应先处理前次失败或显式回退。

状态文件为 `/var/lib/z3cz/deployment/status`，安装待完成记录为同目录的 `install-pending`。迁移失败可能留下部分数据库变更，保留维护，不自动恢复数据库备份。回退脚本继续要求显式选择数据库恢复。

## 自动与人工验收

`bash scripts/host/deployment.test.sh` 在临时目录中模拟 Docker，验证升级成功、启动失败、双重失败、数据库不可用、迁移失败、安装重试和新旧密码挂载选择。

`bash scripts/release/smoke-deploy.sh dist/release` 使用真实发布包，在一次性 Docker-in-Docker 守护进程中验证安装、认证查询、数据库断开恢复、维护期间健康检查、引擎重启后的自动恢复、升级和坏版本回退。它需要特权测试容器，但不挂载宿主机 Docker socket 或业务数据，不发布宿主机端口，退出后删除测试容器及其匿名卷。

Release 工作流在发布前执行上述检查，并通过 `Z3CZ_TEST_LEGACY_REF` 指定未经修改的旧升级脚本来验证第一跳兼容。真实测试使用正式 API、迁移和数据库，不用模拟 API 替代。

发布前另在专用 Desktop/WSL 测试机执行：全新安装、旧版升级、Windows 重启、Desktop 退出再启动，以及新旧挂载路径的密码一致性和数据库哨兵数据保留检查。不得为验收重启正在使用的开发或生产环境。
