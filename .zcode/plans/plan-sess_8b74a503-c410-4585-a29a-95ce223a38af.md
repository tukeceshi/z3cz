# 优化：开关即时反馈 + 失败明确提示

## 问题定位（两处）

1. **开关没反应的直接原因**：`volcano-model-row.tsx:76-81` —— 开关组件在模型"未开通"时直接吞掉点击（`if (checked && enableBlocked) return`），界面毫无变化。
2. **无即时反馈**：`volcano-interface-panel.tsx handleToggle` —— 开关是受控组件，只有成功后才翻转，探活的几秒内界面无任何变化。

失败提示文案已齐备（无需新增）："该模型未在火山控制台开通，请先在开通管理中启用"、"检测开通状态失败"、"更新模型启用状态失败"。

## 改动（两个文件，纯前端）

**1. `volcano-model-row.tsx`（解锁开关）**
- 删除 `enableBlocked` 变量（58 行）及 import 中的 `isVolcanoModelActivationBlocking`；
- `onCheckedChange` 简化为直接透传 `onEnabledChange`，不再吞点击。

**2. `volcano-interface-panel.tsx` `handleToggle`（乐观翻转 + 失败回弹）**
- 进入处理函数时立即乐观更新本地 snapshot 的 `enabled`，开关马上翻转（探活/保存期间配合既有的 `togglingId` 禁用态，呈现"操作中"）；
- 三处失败路径回滚到原 snapshot 并触发既有 toast：探活未通过（blockedEnable，现有代码基于旧 snapshot 合并探活结果，天然完成回滚+状态刷新）、探活请求异常、保存失败（toggleFailed）。

## 效果

点击 2.5 开关 → 立即翻转为开启态（操作中禁用）→ 探活通过则保持开启；未通过则回弹并弹提示"该模型未在火山控制台开通，请先在开通管理中启用"。关闭方向同理。

## 验证

1. 两个文件跑 lint 与类型检查；
2. dev 面板实际点击 2.5 开关观察：立即翻转 → 探活 → 成功保持 / 失败回弹+提示。
